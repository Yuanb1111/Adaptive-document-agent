# Bounded company introduction and actionable failures

The fixed 20-page body policy exempts only Data Index source references and
literal source tables. The introduction remains within five body pages.

The introduction pipeline previously selected audience meanings only when a
whole-file limit existed. A body-only limit skipped that selection and asked the
editor to summarize every substantive Summary passage, including low-level
transaction details, with supporting introduction appendices. Repeated semantic
repairs could exhaust their bounded attempts even after most issues were fixed.

Every bounded introduction now follows complete source reading with model-owned
importance decisions and independent selection review, for both body and
whole-file limits. The writer and independent coverage reviewer preserve every
selected central meaning and its qualifications. Original source passages,
raw values, page citations and include/omit decisions remain in the audit.
Introductions with a section cap or an audience selection cannot add supporting
introduction appendices. No settings or model-provider exceptions are added.

If introduction verification fails, the result remains partial and export stays
blocked. The failure is stored as a diagnostic rather than unsourced company
copy. Both early and late failures identify the introduction stage and original
source-check reason, including for older downloaded results containing the
unavailable-introduction placeholder. The UI points to the existing retry
action. No source pages or successful validation verdicts are fabricated.

The pipeline version changes to invalidate incompatible complete-result caches;
extraction and numerical-analysis cache versions remain unchanged. Existing
failed exports need a new reporting attempt under the corrected pipeline, not
an export of the same unverified introduction.

Regression coverage exercises body, whole-file and introduction-only caps,
reviewed omissions with complete source retention, rejected selection blocking,
appendix rejection, late-failure UI/JSON diagnostics and unchanged export gates.
