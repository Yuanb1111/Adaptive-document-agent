# Introduction meaning corrections and renewable JSON downloads

Introduction importance review distinguishes a rejected include/omit selection
from a defensible selection whose required meanings need correction. In the
latter case, one bounded model patch replaces only the affected included parts'
meaning lists. Python preserves inclusion, omission, reasons, part identities
and exact owned source passages. The full selection and corrected meanings must
then pass independent review; a second rejection still blocks introduction and
PPT delivery. Failed proposals and patches remain in the Summary plan audit,
without being marked as an accepted audience selection. No provider-specific
logic, invented citations or deterministic semantic splitting is introduced.

An incomplete analysis now exposes its JSON before topic finalization or PPT
checks. Normal result JSON downloads also have a dedicated fragment with a
Refresh JSON download link action. This serializes the retained result and
registers the downloadable bytes again, without rerunning analysis or building
PPT. JSON serialization errors remain isolated and redact internal exception
details. Existing combined analysis/PPT diagnostics remain available for
completed analyses.

Streamlit may remove media files after a disconnected session stops referencing
them. A stale browser download URL is not durable result storage. Refreshing the
link can recover it while the result session remains available; it cannot
recover a result already lost from an expired/restarted cloud session. The
application does not share results across users or silently initiate a paid
retry to recover a missing download.

Regression tests cover independently checked meaning splits, unchanged
selection decisions, rejected/invalid patches, canonical evidence binding,
partial-result downloads without PPT work, actual Streamlit media expiration
and re-registration, and format-specific serialization error isolation.
