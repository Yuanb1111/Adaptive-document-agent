# Introduction compression against physical page capacity

The retained `.685` v144 run stopped at the introduction layout boundary. Its
seven selected source parts contained 41 independently approved required
meanings. The first copy contained 705 English words in nine paragraphs and
three logical groups, which occupied seven physical slides. The single layout
revision contained 708 words in eight paragraphs and three groups, still seven
physical slides. It had not reached the independent copy coverage review.

The revision retained repeated business definitions, application lists, listing
basis and loss qualifications. Some heading changes also increased wrapping.
Counting logical groups or paragraphs did not predict readable physical pages.
Those overlapping assertions need semantic synthesis by the model while their
distinct source owners and required meaning references remain intact.

## Changes

- A complete authored theme is packed in its original paragraph order using
  deterministic minimum-page pagination. The former preliminary four-item
  split no longer isolates paragraphs that could share a page. Candidate
  layouts consider the existing one/two-item layout and three/four-item grid;
  an overflowing two-item candidate cannot rule out a readable three-item grid.
  Separate authored themes are not automatically merged.
- Template title and paragraph-heading limits match native export, including
  the numbered heading prefix and the full-width continuation-title reserve.
  Overlong headings enter bounded layout correction without splitting or
  rewriting otherwise complete body copy. An incomplete pagination measurement
  reports unknown physical counts rather than a misleading zero-slide score.
- Layout correction receives the actual template dimensions, title wrapping,
  paragraph height, usable page capacity and physical page allocation, together
  with the exact required-meaning inventory and current paragraph references.
  Full owned source quotations remain in the original source context rather
  than being repeated in every measurement record.
- Each selected-introduction candidate has at most two compression corrections.
  The existing global content-candidate and source/meaning correction budgets
  remain in force. A final correction receives explicit measured progress
  feedback when the first
  remains over budget. Cosmetic changes and fewer logical groups do not count
  as satisfying the physical limit. Every candidate and measurement is audited.
- A compression cannot remove original fact IDs, change the document identity,
  invent source bindings, omit required meaning references, reuse stale quotes
  or attach a meaning to a paragraph without its owning source. Multiple source
  meanings may share one concise supported statement with all their bindings.
- Geometry and author mappings never grant semantic acceptance. The final
  current copy still receives the complete independent source/meaning review.
  Unsupported assertions, lost qualifications and misleading paraphrases remain
  failures even when all reference fields are populated and the layout fits.

The five-slide introduction cap and twenty-slide body cap remain unchanged.
Data Index is counted separately; analysis continuation slides count as body.
No configuration switch, document-specific rule, cloud fallback or new provider
dependency is introduced. Late additive omission correction keeps its protected
copy and cannot invoke a layout rewrite.

## Replay integrity

The external `.685` JSON and original PDF remain outside the repository. Replay
checks their hashes, source document, all 1,623 observations, twelve calculations
and the exact 41-meaning/source-quotation inventory. The extraction-v19 and
analysis-v74 contracts are unchanged; only the fixture's reporting version is
migrated to exercise the new reporting path.

The offline historical replay uses both actual overflowing drafts and exact
bound selection reviews. A missing new compression response stops it without
fabricating an independent acceptance. Separate controlled complete-report
tests exercise successful compression, native PPT export and strict rejection.
Fresh provider validation, when run, is reported separately from retained
historical responses and synthetic fixtures.

The five water/emissions warnings in `.685` are an independent extraction issue:
missing period headers made cross-period observations appear conflicting. They
did not enter that run's calculations and did not trigger its introduction
layout failure. This release does not claim to repair those observations.

## Final budget output recovery

The first live reporting replay passed all 41 independent meaning checks but
stopped later in physical budget selection: 23,097 of the 24,000 output tokens
were reasoning tokens, leaving an incomplete JSON response. That is not a valid
semantic selection, and partial JSON must never be continued or accepted.

A proven length truncation now receives one retry with identical complete input:
selection capacity increases from 24,000 to 40,000 tokens, independent review
from 16,000 to 24,000. This does not spend another semantic proposal. At most two
semantic proposals remain, and every complete candidate still needs exact source
subset validation, complete include/omit decisions, independent omission review,
native physical measurement and final briefing verification. Malformed output
without a length finish reason, privacy, transport and cancellation failures do
not receive capacity retries or cloud fallback.

Failure paths retain earlier proposals, verdicts, actual counts and output
attempt diagnostics, even if a later response never completes. Truncated output
is diagnostic-only and stays out of semantic correction prompts.

The pre-final live checkpoint had five planned introduction pages but six native
pages because of continuation-title reservation. It is retained as a failed
checkpoint. Final validation must use the corrected frozen capacity rules and
new source-checked copy; a planned count alone is not evidence of a five-page
PowerPoint introduction.
