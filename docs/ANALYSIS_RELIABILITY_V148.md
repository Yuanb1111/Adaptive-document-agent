# Source-owned findings and structured introduction (v148)

This update addresses generic source binding and scheduling defects exposed by
the `.655` and `.543` runs. No issuer, document type, page number or financial metric chooses
a production workflow. Raw extraction and calculations remain unchanged.

## Findings and summary retention

Assurance-status repair options retain their exact page, table, row, column and
period. An unknown price column cannot replace an explicitly unaudited revenue
share column for the same period. Deterministic source checks and fresh
independent meaning reviews remain mandatory, with the existing repair budgets.

Residual source patches are accepted independently at their original item
addresses. A failed sibling no longer rolls back a valid correction. Source-valid
items can use their existing bounded meaning-correction opportunity even while
another item remains source-invalid. Every changed item still needs a fresh
independent meaning verdict before inclusion; percentage comparisons still need
both explicit claim endpoints, and sign/representation errors are not waived.

Composition categories must match literal source row labels before they can bind
a numerical endpoint. Separate annual and interim comparisons are checked as
separate complete ranges. This fixes mechanical false rejections without
allowing one category or reporting basis to borrow another's values.

A historical withheld claim continues to constrain the same copy. Revised copy
must pass normal source checks again. Budget-stage recompilation now offers the
existing bounded wording repair before native measurement and independent scope
review. Safe authored questions retain their subject instead of becoming a
generic question about reported values.

## Introduction layout

The existing author request must choose paragraph, comparison, timeline,
relationship or key-metric structure using exact contiguous copy boundaries.
Persisted older introductions retain their optional metadata for compatibility.
Semantic structures participate in the existing independent part-meaning review
and content digest. Invalid or overflowing structures use the established
complete-copy pagination. No relationship, metric, chronology or caption is
inferred by the renderer. Independently authored items can occupy measured,
editable native panels; insufficient space falls back to full-copy pagination.

Older accepted copy can receive only lossless sentence segmentation. All
characters, qualifications, meaning references, fact IDs and page provenance
remain. Missing optional display metadata preserves the historical digest;
an explicit semantic layout requires its own reviewed digest.

## Avoid repeated work

Independent topic corrections and insight batches use the configured shared
gateway concurrency allowance; local and stateful clients retain serial access.
Deterministic introductory reading checks reuse only an exact content-addressed
document, observation set and reading assignment. Audience selection, page
capacity and independent semantic approval are checked separately each time.
Pure quantity parsing caches immutable results. Compact speaker-note JSON avoids
creating thousands of unnecessary OOXML paragraphs while retaining audit data.

Budget substeps now expose proposal numbers and separate selection, compilation,
native measurement, independent review and final-briefing timings. Progress is
event based and does not imply a remaining-time estimate.

Within one budget refinement, exact repeated author requests that already failed
deterministic source/value checks reuse their rejection diagnostics. Complete
source, constraints, schema, model settings and request policy identify a match;
unknown gateway interfaces bypass this optimization. Successful copy, independent
approval, privacy failures and transport failures are never cached by this memo.
The two-proposal local regression reduces four duplicate author requests to two
while still making both independent scope-review calls.

## Parsed fragments and literal rows

A parsed header fragment must not suppress recovery of a complete literal row
that is absent from all parsed rows. Recovery is restricted to a complete row
and its headers inside the same continuous quotation. Existing partial or
unresolved rows retain ownership and ambiguity; conflicting units and columns
remain rejection conditions. This repairs `.543` without changing its accepted
copy or requiring another model request.

## Validation boundary

The pipeline is `v148`, analysis cache is `analysis-v77`, and extraction remains
`extraction-v20`. Focused source-binding, audit-status, concurrency, cache
invalidation and editable-layout regressions accompany the changes. A ten-minute
PDF-to-PPT time is a performance target, not a timeout that permits incomplete
output or bypasses evidence checks. End-to-end results must be reported from an
actual fresh PDF run, separately from local replay and warm CPU measurements.

One authorized fresh `.655` PDF run completed in **724.811 seconds** (12m05),
including extraction, 682.496 seconds of analysis and 38.282 seconds of PPT
export and rendered QA. The output had 18 body slides plus two Data Index slides,
and editorial status `ready`. It made 82 model requests, retained all independent
review gates, and fit the native slide budget without a refinement proposal.
Compared with the archived `.655` run's 1422.077 seconds, elapsed time fell by
about 49%. This run does not prove a ten-minute bound or exercise a live budget
refinement round; those branches have separate local regressions.

The run also exposed batch-coupled briefing loss: three of seven initial items
were removed. Follow-up source-transaction and introduction-structure changes
were made after this live run and are covered by local regressions, not by a
second full model run. The historical run records and code fingerprint remain
unchanged. The `.543` local replay used its unchanged 98 reading parts and five
introduction slides: reading errors fell from 19 to zero, presentation validation
passed, and the actual prepared-introduction attachment succeeded without model
access. A new full `.543` generation and export have not been measured.

The broad local suite was run in separate per-file processes to avoid a native
PPT/XML crash in the long-running Windows test process. AppTest subprocesses
initially timed out before application execution: even an isolated
`asyncio.new_event_loop()` blocked in the sandbox's loopback socket pair. All
167 UI/startup/credential tests passed when rerun with local socket access; no
model requests were made. Focused source, patch lifecycle, memo invalidation,
native export and layout tests were rerun after their final changes. The live
run's rendered QA covered all 20 slides; the later five-page introduction preview
was separately rendered and checked for complete copy and source binding.
