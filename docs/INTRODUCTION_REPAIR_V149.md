# Unified introduction review repair (v149)

The `.510` run exposed a generic recovery defect: one independent verdict
reported both an omitted source part and defects in already included assertions.
The additive repair handled only the omitted part and froze the defective copy.
The next independent review therefore received known unresolved defects and used
the last semantic round to reject them again.

## One complete repair transaction

The existing final finding-resolution operation can handle both kinds of work
in one model request. It retains a disposition for every exact finding, explicit
source-owned edits and additions, and explicit include decisions with a reason
for newly selected parts. Python checks addresses, ownership, complete finding
coverage and protected copy; models still decide truth, importance and meaning.

Untargeted decisions and assertions remain unchanged. A disposition is an author
proposal, never approval. Necessary qualifications cannot be dismissed as
optional background. The next complete independent review must judge all
dispositions, the entire revised union and the original source. Pure omission
and pure meaning recovery remain supported. The maximum three semantic reviews,
one shared binding retry, privacy guards and cancellation behavior are retained.

## Consistent context without inherited acceptance

Later reviews receive a compact history of bound verdicts from this invocation
and this exact source and audience context. It distinguishes prior choices and
reported defects from the current copy. The reviewer must evaluate resolved and
unresolved findings, and explain why newly requested independent background is
material to the same introduction scope. Historical choices do not prevent the
reviewer from identifying a genuine error or necessary qualification.

Canonical quotations and raw readings remain in the audit. The request wire
references shared source and meaning inventories rather than repeating their
full text. No historical approval is reused. Audience-selection time is recorded
even when the introduction fails, so it can be distinguished from reading,
slide writing and PowerPoint export.

## Verification boundary

Pipeline version is `v149`, analysis cache is `analysis-v78`, and extraction
remains `extraction-v20`. Production code contains no issuer, document-type,
page-number or field-specific branch for this fix.

`.510` stopped after 550.272 seconds without exporting a PPT. Its three
independent introduction reviews consumed 332.751 seconds; these times are
failure diagnostics, not evidence of a ten-minute successful generation.
The ten-minute upload-to-PPT target remains a measured performance goal.

Local regressions use retained `.510` source and verdict records. New synthetic
author or reviewer fixtures are explicitly labelled and must not be represented
as real model acceptance.

Local verification resolved **377 distinct tests passed and six skipped** across
the introduction, checkpoint, source-ownership, layout and new mixed-flow suites.
The skipped cases require separately configured private checkpoint fixtures.
Old raw-wire fixtures were updated to inspect the shared meaning inventory or
materialize its exact references; their source and rejection assertions remain.

The retained `.510` prefix plus explicitly synthetic corrected author/reviewer
fixtures verifies that all four second-round findings can be handled together.
The 24 unflagged original meanings and their source ownership remain unchanged;
a rejected, unavailable or stale final verdict cannot approve the result. This
is protocol evidence, not a fresh model acceptance or a new exported PPT.

For the same `.510` second-round input, raw review JSON decreased from 136,109
to 135,956 characters (0.11%). For the same synthetic final candidate, it fell
from 172,346 to 170,912 (0.83%). The complete source remains available once, and
exact-ID references offset the added history. These small input reductions do
not establish a meaningful latency improvement.

## Authorized live run and subsequent local correction

One separately authorized fresh PDF-to-PPT run used the configured DeepSeek
gateway with analysis, extraction and model-response caches disabled. It stopped
after **283.010 seconds** (4m43), before PPT generation, with 46 model requests.
The first independent review returned mixed findings and the new unified route
was invoked. Its complete response was rejected because a 314-character
inclusion rationale exceeded the old 240-character schema limit. This was a
transport-capacity error in audit metadata, not a fresh semantic rejection.

The common audience-decision and inclusion rationale limit is now 2000
characters. Reasons are retained verbatim: none is truncated, rewritten or
invented, and the concise-author preference remains. Over-capacity, missing and
blank reasons still fail the protocol. No model retry was added. The original
complete response passes the local schema, owned patch and canonical decision
gates: all 26 unflagged original meanings remain unchanged. Replay stops at the
next required fresh independent review because no verdict exists for that new
candidate; no synthetic acceptance is substituted. Historical live files and
their pre-correction code fingerprint are preserved. No second model run was
made after this correction, so successful end-to-end generation and the
ten-minute target remain unverified for final v149 code.

The same live run also exposed a nonterminal source-scope selection rationale
of 602 characters exceeding a 600-character limit. That audit-only field now
has a bounded 2000-character allowance too. Complete rationale is preserved;
target count, section bounds, page budget, overlap, literal-evidence and privacy
checks remain unchanged. Its local schema or target-selection success does not
mark any supplementary source as read or checked. Failed and incomplete checks
retain their original status.
