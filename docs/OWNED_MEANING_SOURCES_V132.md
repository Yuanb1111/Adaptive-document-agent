# Canonical source evidence for introduction meanings (v132)

The v131 live validation stopped when a model retyped a quotation that did not
match its owning source part. The model still chooses each assertion and owning
part. Python now copies that part's complete original text as literal evidence,
instead of asking the model to reconstruct an evidence string. This is provenance
binding, not semantic approval.

The independent selection reviewer must verify every assertion against its own
complete original passage, including values, scope, periods, attribution and
uncertainty. A copied source passage does not establish the claim. Unsupported
assertions remain rejected; authoring, numeric validation, final per-meaning
review, physical page limits and export verification remain mandatory.

A proposed model quotation, if provided, is retained only as diagnostic data in
the selection audit. It is excluded from the author, content repair and final
review's required-meaning context. Loaded selections must retain the exact full
owning quotation, the source fingerprint and independent acceptance. Post-review
changes fail the contract and cannot reuse a completion.

Pipeline and analysis versions advance; extraction remains unchanged. Tests
cover original quotation preservation, independently rejected unsupported
assertions, exclusion of reconstructed evidence from author context, and stale
substring replacements. No issuer, metric, product name or document type chooses
this workflow.

The audience section purpose is kept separate from the original document purpose.
The reviewer preserves every qualifier of selected assertions and assesses their
relevance to the introductory section, without demanding unrelated transaction
or analytical detail merely because it appears in the same source passage.
The original document purpose, full reading and raw data remain available.
