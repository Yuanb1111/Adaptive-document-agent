# Source repair progress and explicit presentation controls

The `.312` diagnostic actually ran v128. Its financial introduction theme was
rejected because two paragraphs paraphrased source-listed reporting periods as
`two six-month periods`. The source separately lists the periods but does not
state their count. The literal source gate rejected coefficient `2`.

An initial repair corrected negative accounting signs but retained that inferred
count. Further wording changes still retained the same rejected count. The
diagnostic also had no report requirements, no analysis focus and no introduction
slide budget, so it did not exercise the previously validated 20/5 page path.

## General changes

- Source repairs run the existing complete-claim source checks before returning.
  A proposal must eliminate all errors or strictly reduce the failed-check set.
  Cosmetic changes receive one final targeted correction and otherwise fail.
  Layout and independent semantic review retain their separate bounded stages.
- Joined audit errors retain each paragraph's numeric failures and accounting
  sign errors separately. Shorter messages or a differently named paragraph
  do not establish repair progress.
- Repair instructions explain that rejected coefficients can be spelled out.
  For inferred counts without a literal reported count, the model must use the
  source-listed items/periods or supported qualitative wording. Python does not
  rewrite source facts or assign semantic meaning to a count.
- Visible upload controls default to 20 body slides and 5 introduction slides;
  appendices are separate. Both limits are user configurable and part of the
  request cache identity.
- `PresentationBudget` carries explicit numeric settings into the orchestration
  API. They are bound before the background introduction starts. A model never
  needs to reinterpret those numbers. Free-text requirements still receive
  semantic interpretation and retain failures visibly.
- A retry with different explicit limits rejects its prior checkpoint. Stricter
  free-text limits remain alongside the numeric controls and existing export
  guards enforce the strictest applicable constraint.
- A Brief patch that fixes a strict subset of source failures receives one
  residual correction limited to the remaining failed original items. Source-valid
  findings, labels, quotes and order remain locked. Correcting a rounded number
  to a native coefficient may change its numeric token; fewer failing original
  items also demonstrates progress. The full candidate must pass source checks
  before the separate bounded semantic correction. Invalid claims remain withheld.
- Independent Brief review extracts endpoints only for changes actually asserted
  in audience copy. Separately dated reported facts do not imply a directional
  trend. Existing arithmetic, source association and incompatible-duration checks
  remain unchanged for asserted comparisons.
- Native geometry may split a long introduction paragraph again beneath a long
  title. Every physical continuation now carries its original item/part identity,
  segment index and count. The ordered visible union must equal the complete
  authored/localized paragraph after save/reload. Missing, repeated, reordered,
  altered or unbound continuations fail; notes cannot substitute for visible copy.

The first live entry test also exposed why sending the numeric controls as prose
was insufficient: the model correctly extracted both limits but classified an
appendix-scope clause as a separate slide limit without a number, making the
whole interpretation invalid. The final implementation uses typed controls.

No rejected-number whitelist, document type branch, issuer-specific rule or
source/meaning validation bypass was added. Raw passages, signed table cells,
rejected drafts and repair proposals remain in the audit. All model requests
still go through `LLMGateway`; Local Only protections are unchanged.
